## Ten consequential usability issues

| Rank / reference | Evidence | Researcher's difficulty / impact | Simplest practical improvement |
|---|---|---|---|
| 1 — Saved result appears in the wrong place (A01) | Verified roundtrip, `_prediction_done` and workspace service | Save reports success, pixels remain present, but a reopened prediction can lose its crop offset and calibration. Researchers cannot infer this from a successful save message. | Correct full-transform persistence; include a transform roundtrip regression. Do not rely on another warning to compensate. |
| 2 — Copy compatibility means only shape (A04) | Verified Qt copy | A destination offered as compatible may occupy another world location. The user is required to remember transforms the UI does not check. | Reject incompatible data-to-world mappings and omit those targets from compatible choices. Preserve complete transforms when creating a destination. |
| 3 — Copy can overwrite curated identities (A19) | Verified Qt copy | “Copy selected” sounds additive, but existing curated nonzero pixels disappear. Deletion Undo does not recover Copy. | Summarize conflicting pixels only when present and provide explicit replace/keep/cancel behavior with recovery. No new main-panel controls are necessary. |
| 4 — Local editing can disagree with visible specimen coordinates (A02) | Verified helper geometry | A rotated/sheared image still allows local editing; helper axes no longer match the specimen. A user cannot correct this through careful clicking. | Fix crop-to-world mapping or disable that mode with a specific actionable explanation. |
| 5 — Failed open removes current viewer context (A06) | Verified service; UI confirmation code-reviewed | A user confirms opening another project, then discovers all its assets are missing after their current layer context is gone. | Preflight first and retain rollback; name missing files and offer restoration. Preserve existing explicit clear confirmation. |
| 6 — Dataset modes enforce different prerequisites (A07/A20) | Verified Qt preparation; resolver inspection | A current pair says Dataset ready with shifted labels or an unacknowledged prediction, while Manage pairs/channels blocks analogous inputs. Users learn inconsistent rules. | Reuse one compatibility/provenance validator and show the reason beside the affected source row. |
| 7 — Pixel persistence and project Save have different meanings | Code-reviewed, service rebinding and direct Zarr edit paths | Writable Zarr edits may already be on disk before project Save. A JSON backup is not a historical mask snapshot, and closing without saving cannot reliably mean discard pixels. | Explain this once at writable-store binding and in Save/backup text; distinguish project-state changes from durable pixel edits. Longer-term snapshots should be justified by actual recovery needs. |
| 8 — Full-image action has no usable memory expectation (A15) | Allocation request verified | Users who successfully edit a huge image can reasonably expect Predict entire image to work, then encounter severe RAM pressure. | Estimate output-buffer memory for the selected scope/channels before running; offer current area/box when budget is exceeded. |
| 9 — Channel assignment table exposes many independent decisions | Code-reviewed, `_multilabel_targets.py:_ChannelAssignmentsTable` L111; dialog tests executed | Nine columns combine mask identity, coverage, review acknowledgement, grouping and foreground interpretation. No click-time or task-completion measurement was made. | Keep the off-panel dialog and existing direct naming shortcut; visually prioritize Image → Channel → Mask → Coverage. Explain unknown vs background beside coverage; group secondary options without adding a new panel. Require deliberate coverage choice for newly assigned masks if it can be done without extra repeated work. |
| 10 — Different Undo mechanisms have different lifetimes | Verified A16 and existing cleanup tests; tooltip/source reviewed | Stroke Undo/Redo and Undo last deletion are distinct. Deletion recovery ends on another deletion or panel close and fails after array replacement. Users may assume one global undo history. | Show recovery scope/lifetime in action status and make it explicit before discarding the only recovery record. Preserve the useful behavior that later nonzero edits survive deletion recovery. |

These issues overlap engineering findings intentionally: protecting scientific intent matters more than cosmetic redesign. The table does not claim the channel naming dead-end shown in earlier user screenshots still exists. This commit includes naming in Manage channels, Use mask layers as channels, setup-on-prepare, cancellation handling, and tests for preserving trained task meanings.

## Consistency, cognitive load and accessibility

Strengths: staged Dataset/Models/Train/Inference/Advanced flow; explanatory coverage text; optional patch preview; source selectors refresh; activity log; task/checkpoint history; explicit unknown channel supervision; prediction review gates in multi-image/channel modes; class changes protect trained task semantics. Existing tests validate several of these behaviors, including setup cancellation and missing-model annotation access.

The highest-value visibility improvement is a compact persistent summary of image/target association, task/output mode, active dataset/split, selected checkpoint and prediction-vs-reviewed status using state already held by the application. Do not duplicate the nine-column editor on the Dataset page. Checkpoint selection and active training settings are different states and must remain visibly distinct.

Keyboard focus order, screen-reader labels, high-DPI clipping, contrast across themes, modal dialog discoverability, real progress latency and long-task cancellation remain **unverified**. Programmatic clicks and stylesheet tests are not an accessibility or usability study.

## Reproducible human follow-up

Use copies of a small microscopy project and a sparse large Zarr project. Ask at least one novice and one experienced annotator to complete the fourteen-step workflow without coaching. Record completion, errors/recovery, panel switches, horizontal scrolling, task time and whether they can identify image, truth, coverage, split and checkpoint at each step. Include changing a channel name after training, a missing asset, a conflicting Copy and a near-boundary review cell. Repeat on a real desktop at 1280×800 and high DPI. Do not use these proposed sessions as evidence until performed.
